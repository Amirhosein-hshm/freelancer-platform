## 1. How to Read This Document

### 1.1 Architecture layers (Phase 1)

```
presentation (Phase 2)   FastAPI routers, Pydantic schemas, DI, global error handlers
application  (Phase 1)   Use Cases (Command pattern), DTOs, shared ports, application errors
domain       (Phase 1)   Entities, Value Objects, Enums, Domain Exceptions, Repository
                         Interfaces, Domain Services
infrastructure (Phase 2) SQLAlchemy repos, JWT/password hasher, file storage, notifications
```

**Dependency rule:** dependencies point only inward. `domain` imports nothing from
`application`/`infrastructure`/`presentation`. `application` imports only `domain` + the shared
ports defined in `application/shared`. No framework imports (`fastapi`, `sqlalchemy`,
`pydantic`, …) are allowed in `domain`/`application` (verified: none exist).

### 1.2 Conventions

| Concern | Convention |
|---|---|
| Files / packages | `snake_case` |
| Classes | `PascalCase` |
| Port / interface | prefix `I` (e.g. `IUserRepository`, `ITokenService`) |
| Exceptions | suffix `Error`; must inherit the shared hierarchy, never raw `Exception` |
| Use cases | suffix `UseCase`; one public method `execute(request: TRequest) -> TResponse` |
| Command / Query DTOs | suffix `Command` / `Query`, frozen dataclass, optional `validate()` |
| Result DTOs | suffix `Result`, frozen dataclass |
| Enum values | `UPPER_SNAKE` members with lower-case string `.value` (DBML-aligned) |
| Permission constants | module-level `PERMISSION_*` string constants near the top of use-case modules |
| Owned-action authorization | `authorize_owned_action(authz, actor_id, owner_id, own_perm, any_perm)` — owner needs `own_perm`, everyone else needs `any_perm` (admin) |
| IDs | `EntityId = str` (type alias), generated by `IIdGenerator` in the application layer |

### 1.3 Error hierarchy & HTTP mapping (Phase 2 contract)

```
Exception
├── DomainError                       (domain/shared/exceptions.py)
│   ├── EntityNotFoundError                  -> HTTP 404
│   ├── InvalidStateTransitionError          -> HTTP 409
│   ├── BusinessRuleViolationError           -> HTTP 422
│   └── UniqueConstraintViolationError       -> HTTP 409
└── ApplicationError                  (application/shared/exceptions.py)
    ├── PermissionDeniedError                -> HTTP 403
    ├── ValidationError                      -> HTTP 400
    │   └── FormValidationError
    └── ExternalServiceError                 -> HTTP 502/503
```

Use-case contract: authorize first, then validate input, then mutate via the entity/domain
service. `EntityNotFoundError` subclasses raised by repositories propagate unchanged.

### 1.4 Cross-context business rules (must live in Entity / Domain Service)

1. A `Project` has **at most one** `selected_application_id` → `Project.assign_freelancer`.
2. A supervisor only reviews projects in **their own categories** → `is_supervisor_of` grants
   `review.decide_own`; any other actor needs `review.decide_any` (admin).
3. A freelancer may only apply to projects **their level permits** → `FreelancerEligibilityPolicy`.
4. **Maximum 3 revisions** per project → `RevisionPolicy.ensure_can_request_new_revision`
   (enforced on every revision-creating path — see §7.5).
5. A completed/cancelled project is **locked** (`Project.is_locked()`) and every mutator guards it.
6. Rating is **only allowed after completion** → `ProjectNotCompletedError`.
7. Freelancer approval is an **authorization** rule, checked with `IAuthorizationService`.
8. Reporting is **read-only** → no mutable entity/aggregate in the reporting context.
9. Owned-resource mutations use the two-tier convention `<res>.<action>_own` / `_any` via
   `authorize_owned_action`; the four system roles are immutable for removal/revocation.

## 2. Shared Kernel

Location: `src/app/domain/shared/` and `src/app/application/shared/`.

### 2.1 Domain base classes

- **`Entity`** (`domain/shared/entity.py`) — abstract, `@dataclass(eq=False, kw_only=True)`.
  Fields: `id: EntityId`, `created_at: datetime`, `updated_at: datetime | None = None`.
  Equality/hash are **identity-based** (by `id`). Subclasses must keep `@dataclass(eq=False)`.
- **`AggregateRoot(Entity)`** — adds `_domain_events: list[DomainEvent]` (not part of equality),
  `pull_domain_events()`, `_record_event(event)`. **No Phase-1 flow records events**; the
  machinery exists but `IEventPublisher` is not wired (see ARCHITECTURE.md §6).
- **`ValueObject`** (`domain/shared/value_object.py`) — abstract `@dataclass(frozen=True)`,
  equality over all fields.
- **`EntityId`** (`domain/shared/types.py`) — `type EntityId = str`.
- **`authorize_owned_action`** (`application/shared/authorization.py`) — shared helper for the
  two-tier ownership convention (see AUTHORIZATION.md §3.1): if `actor_id == owner_id` it requires
  the `own` permission, otherwise it requires the `any` (admin) permission. Used by the project,
  feedback, and ticketing contexts.
- **`DomainEvent` / `IEventPublisher`** (`domain/shared/events.py`) — frozen dataclass base +
  `publish(list[DomainEvent])` port. Unused in Phase 1.

### 2.2 Application shared ports (`application/shared/ports.py`)

All external/cross-cutting dependencies are ports implemented in Phase 2
(`infrastructure`) and injected via constructor; tests use Fakes.

| Port | Responsibility | Notes |
|---|---|---|
| `IPasswordHasher` | `hash(plain) -> str`, `verify(plain, hashed) -> bool` | argo2/bcrypt in Phase 2 |
| `ITokenService` | `generate_access_token(user_id, roles)`, `generate_refresh_token() -> (raw, jti)`, `hash_refresh_token(raw)`, `decode_access_token(token) -> AccessTokenPayload` | raw token handed to user once; only hash stored |
| `IClock` | `now() -> datetime` | deterministic time in tests |
| `IIdGenerator` | `new_id() -> EntityId` | UUID4 in Phase 2 |
| `IUnitOfWork` | context manager; `commit()`, `rollback()` | `__exit__` must roll back on exception |
| `INotificationService` | `send_email`, `send_verification_email`, `send_password_reset_email` | email in Phase 2 |
| `IFileStorageService` | `get_metadata(file_asset_id) -> FileAssetMetadata`, `register_uploaded_file(...)` | file asset storage |
| `IProjectCodeGenerator` | `next_code(year) -> str` (`PRJ-2026-001`) | per-year sequence |
| `ITicketCodeGenerator` | `next_code(year) -> str` (`TCK-2026-001`) | added Phase 8, mirrors project codes |
| `IEventPublisher` | re-export of domain port | unused in Phase 1 |
| `IAuthorizationService` (`application/shared/authorization.py`) | `has_permission(user_id, key) -> bool`, `require_permission(user_id, key)` (raises `PermissionDeniedError`), `has_role(user_id, role_key) -> bool` | RBAC join in Phase 2 |

Value objects in ports: `AccessTokenPayload(user_id, roles, expires_at)`,
`FileAssetMetadata(file_asset_id, file_name, size_bytes, mime_type, url, uploaded_at)`.

Permission keys follow `"<resource>.<action>"` (e.g. `project.create`, `form.manage`,
`reporting.read`) and are declared as module-level `PERMISSION_*` constants. Owned resources
use the two-tier pair `<resource>.<action>_own` / `<resource>.<action>_any` via
`authorize_owned_action`; the four system roles (`admin`, `customer`, `freelancer`,
`supervisor`) are protected from removal/revocation by `SystemRoleImmutableError` (see
AUTHORIZATION.md).

### 2.3 Shared exceptions

- Domain: `DomainError` → `EntityNotFoundError`, `InvalidStateTransitionError`,
  `BusinessRuleViolationError`, `UniqueConstraintViolationError`.
- Application: `ApplicationError` → `PermissionDeniedError`, `ValidationError` →
  `FormValidationError`, `ExternalServiceError`.

## 3. IAM / RBAC

Location: `src/app/domain/iam/`, `src/app/application/iam/`.

### 3.1 Domain purpose

- **Business problem:** identity registration/authentication, session management via
  refresh tokens, and role-based access control (users, roles, permissions).
- **Responsibilities:** user lifecycle (`PENDING → ACTIVE → BLOCKED`), authentication
  (login/refresh/logout/change-password/forgot-password), RBAC (assign/remove roles,
  grant/revoke permissions), token issuance & rotation.
- **Must NOT be responsible for:** authorization decisions inside other contexts
  (those call `IAuthorizationService`), freelancer-specific approval state
  (that lives in the freelancer context), or any project/domain logic.

### 3.2 Value Objects (`domain/iam/value_objects.py`)

| VO | Attribute | Validation |
|---|---|---|
| `Email` | `value: str` | regex `^[^@\s]+@[^@\s]+\.[^@\s]+$`; raises `InvalidEmailError` |
| `PhoneNumber` | `value: str` | regex `^\+?[0-9][0-9\s\-()]{6,19}$`; raises `InvalidPhoneNumberError` |
| `PasswordHash` | `value: str` | none — pure wrapper; hashing happens via `IPasswordHasher` |

### 3.3 Enum

`UserStatus`: `PENDING`, `ACTIVE`, `BLOCKED`, `ARCHIVED`.

### 3.4 Entities

#### User (AggregateRoot)

- **Why it exists:** the single identity record for every actor (customer, freelancer, admin).
- **Attributes:** `email: Email`, `phone: PhoneNumber | None`, `password_hash: PasswordHash`,
  `first_name`, `last_name`, `status: UserStatus`, `email_verified_at`, `phone_verified_at`,
  `last_login_at`, `password_changed_at`, `deleted_at` (all timestamps nullable).
- **Business rules / state machine:**
  - `activate()` — `PENDING/BLOCKED → ACTIVE`; raises `InvalidStateTransitionError` if
    `ARCHIVED`; no-op if already `ACTIVE`. This is the **only** activation path (no
    email-verification use case exists).
  - `block(reason)` — `ACTIVE/PENDING → BLOCKED`; raises if `ARCHIVED` or already `BLOCKED`
    (`UserAlreadyBlockedError`). **Note:** `reason` is accepted but never stored.
  - `record_login(at)` — sets `last_login_at`.
  - `change_password(new_hash, at)` — sets hash + `password_changed_at`.
  - `soft_delete(at)` — sets `deleted_at`; **no use case calls it.**
  - `is_active()` — `status == ACTIVE and deleted_at is None`.

#### Role (Entity)

- `role_key` (immutable business key), `name`, `description`, `is_system`.
- `rename(name)` — renames a role (key never changes). **No use case calls `rename`.**
- `is_system` roles are conceptually protected from deletion (no delete use case exists).

#### Permission (Entity)

- `permission_key`, `module`, `action`, `description`, `is_system`. Data-only.

#### UserRole (Entity)

- Links `user_id` ↔ `role_id`, `assigned_by_user_id`, `assigned_at`, `revoked_at`,
  `is_active` (default `True`).
- `revoke(at)` — soft revocation; raises `InvalidStateTransitionError` if already revoked.

#### RolePermission (Entity)

- Links `role_id` ↔ `permission_id`, `granted_by_user_id`, `granted_at`.
- **No soft-revocation** — `revoke` is a hard delete via `IRolePermissionRepository.remove`.

#### RefreshToken (Entity)

- `user_id`, `jti`, `token_hash`, `issued_at`, `expires_at`, `device_name`, `ip_address`,
  `user_agent`, `revoked_at`, `replaced_by_token_id` (rotation chain).
- `is_valid(now)` — `revoked_at is None and expires_at > now`.
- `revoke(at, replaced_by=None)` — idempotent (no double-revoke guard).

### 3.5 Repository interfaces

- `IUserRepository`: `add`, `get_by_id` (raises `UserNotFoundError`), `find_by_id`,
  `get_by_email`, `exists_by_email`, `update`, `list_by_status`.
- `IRoleRepository`: `get_by_id`, `get_by_key` (raise `RoleNotFoundError`), `list_all`, `add`.
- `IPermissionRepository`: `get_by_id`, `list_by_module`.
- `IUserRoleRepository`: `add`, `find_active`, `list_active_roles_for_user`, `update`.
- `IRolePermissionRepository`: `add`, `list_permissions_for_role`, `remove`.
- `IRefreshTokenRepository`: `add`, `get_by_jti`, `find_by_token_hash`, `update`,
  `revoke_all_for_user`.

Several methods are defined for future/admin use and unused today: `IUserRepository.list_by_status`,
`IRoleRepository.add`, `IPermissionRepository.list_by_module`,
`IRolePermissionRepository.list_permissions_for_role`, `IRefreshTokenRepository.revoke_all_for_user`.

### 3.6 Domain exceptions

`UserNotFoundError`, `DuplicateEmailError`, `InvalidCredentialsError`,
`UserAlreadyBlockedError`, `UserNotActiveError`, `InvalidRefreshTokenError`,
`RefreshTokenNotFoundError`, `RoleNotFoundError`, `PermissionNotFoundError`,
`UserRoleNotFoundError`, `RoleAlreadyAssignedError`, `SystemRoleImmutableError`,
`PermissionAlreadyGrantedError`, `InvalidEmailError`, `InvalidPhoneNumberError`.

> **Dead code:** `RoleNotFoundError` and `PermissionNotFoundError` are raised only by (future)
> repository implementations. `SystemRoleImmutableError` (previously unused) is **now raised**
> by `RemoveRoleUseCase` and `RevokePermissionUseCase` for `is_system` roles.

## RegisterUser

### Purpose
Registers a new user and assigns the default `customer` role.

### Actor
Anonymous visitor (self-service).

### Input (`RegisterUserCommand`)
- `email: str`
- `password: str`
- `first_name: str`
- `last_name: str`

### Output (`RegisterUserResult`)
`user_id`, `email`, `status` (`"pending"`), `created_at`.

### Dependencies
`IUserRepository`, `IUserRoleRepository`, `IRoleRepository`,
`IPasswordHasher`, `IIdGenerator`, `IClock`, `INotificationService`, `IUnitOfWork`.
Constant: `DEFAULT_REGISTER_ROLE_KEY = "customer"`.

### Flow
1. `request.validate()` — email/password/names must be non-blank.
2. Build `Email` (raises `InvalidEmailError` on bad format).
3. `exists_by_email` → `DuplicateEmailError` if taken.
4. `role_repo.get_by_key("customer")` → `RoleNotFoundError` if the role is not seeded.
5. Hash password; build `User(status=PENDING, phone=None)`.
6. Build `UserRole(assigned_by_user_id=user.id, assigned_at=now)`.
7. In UoW: `user_repo.add`, `user_role_repo.add`, `commit`.
8. Generate `verification_token` and call `send_verification_email` (after commit).

### Business rules
- Duplicate emails rejected; new users start `PENDING`; default role = `customer`.

### Errors
`ValidationError`, `InvalidEmailError`, `DuplicateEmailError`, `RoleNotFoundError`.

### Side effects
Creates `User` + `UserRole`; sends verification email.

> **Gap:** the verification token is generated and emailed but **never persisted**, so no
> flow can later consume it. There is no email-verification use case; a PENDING user is
> activated only by an admin via `ActivateUser`.

## LoginUser

### Purpose
Authenticates a user and issues access + refresh tokens.

### Actor
Registered user.

### Input (`LoginUserCommand`)
- `email: str`
- `password: str`

### Output (`LoginUserResult`)
`user_id`, `email`, `access_token`, `refresh_token` (raw, one-time), `refresh_token_jti`.

### Dependencies
`IUserRepository`, `IUserRoleRepository`, `IRefreshTokenRepository`,
`IPasswordHasher`, `ITokenService`, `IIdGenerator`, `IClock`, `IUnitOfWork`.
Constant: `REFRESH_TOKEN_TTL = 30 days`.

### Flow
1. `request.validate()`; build `Email`.
2. `get_by_email` — a missing user is converted to `InvalidCredentialsError`
   (anti email-enumeration).
3. `password_hasher.verify` → `InvalidCredentialsError` on mismatch.
4. `user.status != ACTIVE` → `UserNotActiveError`.
5. Load active role keys → `generate_access_token(user.id, roles)`.
6. `generate_refresh_token()` → store `RefreshToken(token_hash=hash(raw), expires=now+30d)`.
7. In UoW: add token, `user.record_login(now)`, `user_repo.update`, commit.

### Errors
`ValidationError`, `InvalidEmailError`, `InvalidCredentialsError`, `UserNotActiveError`,
`UserNotFoundError` (repository), `ExternalServiceError` (token failure).

### Side effects
New `RefreshToken` row; updates `last_login_at`.

> **Note:** unlike `RefreshTokenUseCase`, login checks only `status` — a user with a
> `deleted_at` stamp but `ACTIVE` status would still pass. `deleted_at` is never set in Phase 1.

## LogoutUser

### Purpose
Revokes a refresh token on logout.

### Actor
Authenticated user.

### Input (`LogoutUserCommand`)
- `refresh_token_jti: str`

### Output (`LogoutUserResult`)
`user_id`.

### Dependencies
`IRefreshTokenRepository`, `IClock`, `IUnitOfWork`.

### Flow
1. `get_by_jti` → `RefreshTokenNotFoundError` if absent.
2. `token.revoke(now)`; `update`; commit.

### Errors
`RefreshTokenNotFoundError`.

### Side effects
Token marked revoked.

> **Notes:** no authorization check (any caller with the jti can revoke it);
> revocation is idempotent, so double-logout succeeds silently.

## RefreshToken

### Purpose
Exchanges a valid refresh token for a new access token (with mandatory rotation).

### Actor
Authenticated user (holds a valid refresh token).

### Input (`RefreshTokenCommand`)
- `raw_refresh_token: str`

### Output (`RefreshTokenResult`)
`access_token`, `refresh_token` (new raw), `refresh_token_jti`.

### Dependencies
`IRefreshTokenRepository`, `IUserRepository`, `IUserRoleRepository`,
`ITokenService`, `IIdGenerator`, `IClock`, `IUnitOfWork`.

### Flow
1. Hash the raw token; `find_by_token_hash`.
2. `token is None or not token.is_valid(now)` → `InvalidRefreshTokenError`.
3. `user_repo.get_by_id`; `user.is_active()` → `UserNotActiveError` (checks status **and** `deleted_at`).
4. Load roles; issue new access token.
5. Rotation (mandatory): create new `RefreshToken`, then in UoW
   `old.revoke(now, replaced_by=new.id)`, `update(old)`, `add(new)`, commit.

### Errors
`InvalidRefreshTokenError`, `UserNotActiveError`, `UserNotFoundError`.

### Side effects
Old token revoked and chained to the new token.

## ChangePassword

### Purpose
Changes the password of the current user after verifying the old one.

### Actor
Authenticated user (acting on themselves via `user_id`).

### Input (`ChangePasswordCommand`)
- `user_id`, `old_password`, `new_password`

### Output (`ChangePasswordResult`)
`user_id`, `password_changed_at`.

### Dependencies
`IUserRepository`, `IPasswordHasher`, `IClock`, `IUnitOfWork`.

### Flow
1. `request.validate()`.
2. `get_by_id` → `UserNotFoundError`.
3. Verify `old_password` → `InvalidCredentialsError` on mismatch.
4. Hash new password; `user.change_password(...)`; update; commit.

### Errors
`ValidationError`, `UserNotFoundError`, `InvalidCredentialsError`.

### Side effects
Updates hash + `password_changed_at`. **Existing sessions/tokens are not revoked.**

> **Gaps:** no check that `new_password != old_password`; no password-strength rule; no
> requirement that the user be `ACTIVE`; no authorization — any caller who knows the user_id
> and old password passes.

## ForgotPassword

### Purpose
Emails a one-time password-reset token to a user who forgot their password.

### Actor
Anonymous (claims an email).

### Input (`ForgotPasswordCommand`)
- `email: str`

### Output (`ForgotPasswordResult`)
`email`.

### Dependencies
`IUserRepository`, `IIdGenerator`, `INotificationService`.
(No clock, no UoW — read + email only.)

### Flow
1. `request.validate()`; build `Email`.
2. `user_repo.exists_by_email(email)` — **no user lookup**, so a missing email is
   indistinguishable from a found one (anti email-enumeration).
3. Only if the email exists: `token = id_generator.new_id()`;
   `send_password_reset_email(email.value, token)`.
4. Always return `ForgotPasswordResult(email=email.value)`.

### Errors
`ValidationError`, `InvalidEmailError`.

### Side effects
Sends a password-reset email only when the email is registered.

> **Gaps:** the token is never persisted or given an expiry, and there is **no reset-password
> use case** to consume it (unchanged). The enumeration leak is fixed — the email existence
> probe no longer surfaces `UserNotFoundError`.

## BlockUser

### Purpose
Blocks a target user account (admin action).

### Actor
User with permission `user.block`.

### Input (`BlockUserCommand`)
- `actor_id`, `target_user_id`, `reason: str`

### Output (`BlockUserResult`)
`user_id`, `status`.

### Dependencies
`IAuthorizationService`, `IUserRepository`, `IClock`, `IUnitOfWork`
(`clock` injected but unused).

### Flow
1. `require_permission(actor_id, "user.block")`.
2. `get_by_id` → `UserNotFoundError`.
3. `user.block(reason)`; update; commit.

### Errors
`PermissionDeniedError`, `UserNotFoundError`, `UserAlreadyBlockedError`,
`InvalidStateTransitionError` (if `ARCHIVED`).

### Side effects
User status → `BLOCKED`. **Reason is discarded** (no `blocked_reason` field).

## AssignRole

### Purpose
Assigns a role to a target user (admin action).

### Actor
User with permission `user.assign_role`.

### Input (`AssignRoleCommand`)
- `actor_id`, `target_user_id`, `role_key: str`

### Output (`AssignRoleResult`)
`user_role_id`, `user_id`, `role_id`.

### Dependencies
`IAuthorizationService`, `IUserRepository`, `IRoleRepository`, `IUserRoleRepository`,
`IIdGenerator`, `IClock`, `IUnitOfWork`.

### Flow
1. `require_permission(actor_id, "user.assign_role")`.
2. `get_by_id(target)`; `role_repo.get_by_key(role_key)`.
3. Duplicate guard: `find_active(user, role)` → `RoleAlreadyAssignedError`.
4. Build `UserRole(assigned_by_user_id=actor_id)`; add; commit.

### Errors
`PermissionDeniedError`, `UserNotFoundError`, `RoleNotFoundError`, `RoleAlreadyAssignedError`.

### Side effects
New active `UserRole` row.

> **Gaps:** no check that the target user is active; no `is_system` protection.

## RemoveRole

### Purpose
Soft-revokes a role from a target user (admin action).

### Actor
User with permission `user.remove_role`.

### Input (`RemoveRoleCommand`)
- `actor_id`, `target_user_id`, `role_key: str`

### Output (`RemoveRoleResult`)
`user_id`, `role_id`, `revoked_at`.

### Dependencies
`IAuthorizationService`, `IUserRepository`, `IRoleRepository`, `IUserRoleRepository`,
`IClock`, `IUnitOfWork`.

### Flow
1. `require_permission(actor_id, "user.remove_role")`.
2. Load user (`get_by_id`) and role (`get_by_key`); if `role.is_system` →
   `SystemRoleImmutableError`.
3. `find_active` → `UserRoleNotFoundError` if none.
4. `user_role.revoke(now)`; update; commit.

### Errors
`PermissionDeniedError`, `UserNotFoundError`, `RoleNotFoundError`, `UserRoleNotFoundError`,
`SystemRoleImmutableError`.

### Side effects
User-role link set `is_active=False`, `revoked_at=now`.

> **Updated:** system roles can no longer be removed (`SystemRoleImmutableError`); previously
> this use case performed no authorization and had no system-role guard.

### Purpose
Grants a permission to a role (admin action).

### Actor
User with permission `user.grant_permission`.

### Input (`GrantPermissionCommand`)
- `actor_id`, `role_id`, `permission_id`

### Output (`GrantPermissionResult`)
`role_id`, `permission_id`.

### Dependencies
`IAuthorizationService`, `IRoleRepository`, `IPermissionRepository`,

### Flow

`PermissionDeniedError`, `RoleNotFoundError`, `PermissionNotFoundError`,
`PermissionAlreadyGrantedError`.

### Side effects
New `RolePermission` row.

> **Updated:** the duplicate check is now enforced at the application level (previously left to
> the repository).

## RevokePermission

### Purpose
Removes a permission from a role (admin action).

### Actor
User with permission `user.revoke_permission`.

### Input (`RevokePermissionCommand`)
- `actor_id`, `role_id`, `permission_id`

### Output (`RevokePermissionResult`)
`role_id`, `permission_id`.

### Dependencies

## 4. Freelancer Management

Location: `src/app/domain/freelancer/`, `src/app/application/freelancer/`.

### 4.1 Domain purpose

- **Business problem:** onboards and governs the freelancer side of the marketplace —
  profile, approval workflow, skill levels, resume, and portfolio.
- **Responsibilities:** freelancer profile lifecycle (`PENDING → APPROVED/REJECTED/SUSPENDED`),
  level assignment & history, resume versioning, portfolio item management.
- **Must NOT be responsible for:** project applications/deliveries (project context),
  ratings (feedback context), or eligibility decisions when applying (that logic lives in the
  project context's `FreelancerEligibilityPolicy` but reads freelancer data).

### 4.2 Enums

- `FreelancerApprovalStatus`: `PENDING`, `APPROVED`, `REJECTED`, `SUSPENDED`.
- `FreelancerLevelAccessType`: `STANDARD`, `RESTRICTED`, `PREMIUM`.

### 4.3 Entities

#### FreelancerLevel (Entity)

- **Why it exists:** defines the tiers that gate a freelancer's access to projects.
- **Attributes:** `level_key`, `name`, `rank_order`, `access_type`,
  `min_completed_projects`, `min_rating: Decimal | None`, `max_active_applications: int | None`,
  `can_apply_public_projects`, `can_apply_private_projects`, `is_active`.
- **Methods:** `deactivate()`. (No `activate()`.)
- **Rules:** eligibility is evaluated by `FreelancerEligibilityPolicy` (§7), which reads these
  flags but **does not check `is_active`**.

#### FreelancerProfile (AggregateRoot)

- **Why it exists:** the freelancer persona bound to a `User`; carries approval state and
  level that gate project participation.
- **Attributes:** `user_id`, `current_level_id: EntityId | None`, `approval_status`,
  `approved_by_user_id`, `approved_at`, `approval_note`, `display_name`, `headline`, `bio`,
  `country_code`, `city`, `timezone`, `hourly_rate_min`, `hourly_rate_max`, `is_available`,
  `deleted_at`.
- **State machine:**
  - `submit_for_approval()` — from `PENDING`/`REJECTED` → `PENDING` (resubmission allowed);
    else `InvalidStateTransitionError`.
  - `approve(admin_id, at, note)` — from `PENDING`/`REJECTED` → `APPROVED`; raises
    `FreelancerAlreadyApprovedError` if already `APPROVED`, `InvalidStateTransitionError` if
    `SUSPENDED`. Stamps `approved_by_user_id`/`approved_at`/`approval_note`.
  - `reject(admin_id, at, note)` — raises only if already `APPROVED`; **`SUSPENDED → REJECTED`
    is legal** (the only coded exit from SUSPENDED). Note: it writes into the `approved_*`
    audit fields even though this is a rejection.
  - `suspend(admin_id, at, note)` — only from `APPROVED`. **No use case calls it** (see §12).
  - `change_level(new_level_id)` — unconditional setter (no existence/activity/approval checks).
  - `is_approved()` — `status == APPROVED and deleted_at is None`.
  - `set_availability(available)` — **unreachable from any use case** (no `is_available` in DTOs).
  - `update_rate_range(min_rate, max_rate)` — raises `InvalidRateRangeError` when both are
    non-`None` and `min > max`. Accepts open-ended ranges (only one side set).

#### FreelancerLevelHistory (Entity)

- Records level changes: `freelancer_profile_id`, `old_level_id`, `new_level_id`,
  `assigned_by_user_id`, `reason`, `assigned_at`. Written by `ApproveFreelancer` (only on a
  level change) and `AssignFreelancerLevel` (always).

#### Resume (Entity)

- `freelancer_profile_id`, `file_asset_id`, `version_no`, `summary`, `is_current`.
- `mark_as_current()` sets `is_current=True` — **never used**; the upload use case mutates
  `is_current` directly. No `mark_as_not_current()`.

#### PortfolioItem (Entity)

- `freelancer_profile_id`, `title`, `description`, `external_url`, `file_asset_id`,
  `display_order`, `is_featured`, `deleted_at`. Data-only. Deletion is a **hard delete** via
  the repository despite the `deleted_at` field.

### 4.4 Repository interfaces

`IFreelancerProfileRepository` (`add`, `get_by_id`, `get_by_user_id`, `update`,
`list_by_approval_status`, `list_available_for_level`),
`IFreelancerLevelRepository` (`get_by_id`, `get_by_key`, `list_active`),
`IFreelancerLevelHistoryRepository` (`add`, `list_by_profile`),
`IResumeRepository` (`add`, `update`, `list_by_profile`, `get_current`),
`IPortfolioItemRepository` (`add`, `get_by_id`, `list_by_profile`, `update`, `delete`).

> `IFreelancerLevelRepository.get_by_key`, `IFreelancerLevelHistoryRepository`, and
> `IResumeRepository.update` are code additions not listed in `DOMAIN.md`. Several list
> methods are unused by application use cases (future reporting/admin queries).

### 4.5 Domain exceptions

`FreelancerProfileNotFoundError`, `FreelancerLevelNotFoundError`, `ResumeNotFoundError`,
`PortfolioItemNotFoundError`, `DuplicateFreelancerProfileError`, `FreelancerAlreadyApprovedError`,
`FreelancerNotApprovedError` (raised in the **project** context), `InvalidRateRangeError`.

## 5. Category Management

Location: `src/app/domain/category/`, `src/app/application/category/`.

### 5.1 Domain purpose

- **Business problem:** organizes projects into a hierarchical taxonomy and governs which
  users act as **supervisors** for a category (supervisors QA the category's deliveries).
- **Responsibilities:** category CRUD (soft delete), supervisor assignment/revocation,
  listing categories and their projects.
- **Must NOT be responsible for:** the actual review decisions (review context), or the
  meaning of a "supervisor of X" check inside other contexts — those reuse
  `ICategorySupervisorRepository.is_supervisor_of`.

### 5.2 Entities

#### Category (Entity)

- **Why it exists:** a taxonomic node (optionally nested via `parent_category_id`) that
  projects and form templates are bound to.
- **Attributes:** `parent_category_id`, `category_key` (immutable), `name`, `slug`,
  `description`, `is_active` (default True), `sort_order` (default 0), `deleted_at`.
- **Methods:**
  - `deactivate()` — sets `is_active=False`.
  - `rename(name, slug)` — renames (no entity-level validation).
  - `soft_delete(at)` — sets `deleted_at` + `is_active=False`. No guard against repeat calls,
    children, or existing projects.

#### CategorySupervisor (Entity)

- **Why it exists:** links a user to a category as a (QA) supervisor.
- **Attributes:** `category_id`, `supervisor_user_id`, `assigned_by_user_id`, `is_primary`,
  `is_active`, `assigned_at`, `revoked_at`.
- **Methods:** `revoke(at)` — soft revoke; raises `InvalidStateTransitionError` if already inactive.
  `promote()` — sets `is_primary=True`; used by `RemoveSupervisorUseCase` to promote the next
  active supervisor after the primary is revoked.

### 5.3 Repository interfaces

`ICategoryRepository` (`add`, `get_by_id`, `get_by_slug`, `list_active`, `update`),
`ICategorySupervisorRepository` (`add`, `list_active_supervisors`,
`list_categories_for_supervisor`, `is_supervisor_of`, `update`).

### 5.4 Domain exceptions

`CategoryNotFoundError`, `DuplicateCategorySlugError`, `SupervisorAlreadyAssignedError`,
`SupervisorAssignmentNotFoundError` (code addition).

- `FormFieldType` (14): `TEXT`, `TEXTAREA`, `NUMBER`, `DECIMAL`, `BOOLEAN`, `DATE`, `DATETIME`,
  `EMAIL`, `PHONE`, `URL`, `SELECT`, `MULTI_SELECT`, `FILE`, `JSON`.
- `FormTemplateStatus`: `DRAFT`, `PUBLISHED`, `ARCHIVED`.

> `ARCHIVED` is terminal and **unreachable** — no use case or entity method ever transitions
> into it (it is only a guard in `publish()`).

### 6.3 Entities

#### FormTemplate (AggregateRoot)

- **Why it exists:** a versioned, category-scoped questionnaire.
- **Attributes:** `category_id`, `template_key`, `name`, `version_no`, `status`,
  `is_active`, `published_by_user_id`, `published_at`, `fields: list[FormField]`, `deleted_at`.
- **Business rules:**
  - `add_field(field)` / `remove_field(field_id)` — only when `status == DRAFT`
    (`require_draft` → `InvalidStateTransitionError`). Duplicate `field_key` →
    `DuplicateFieldKeyError`; missing field → `FieldNotFoundError`.
  - `publish(published_by, at)` — requires **at least one field** (`FormTemplateHasNoFieldsError`);
    already `PUBLISHED` → `FormTemplateAlreadyPublishedError`; `ARCHIVED` →
    `InvalidStateTransitionError`. Sets `published_at`/`published_by`/`is_active=True`.
  - `new_draft_version(new_version_no, at)` — deep-ish copy for versioning; new field ids are
    composite (`<template_id>:<field_key>`); **options are shallow-copied (shared references)**.
    Any status can spawn a new draft.
  - `require_draft(action)` — guard used by the draft-editing use cases.

#### FormField (Entity)

- **Attributes:** `field_key`, `label`, `description`, `field_type`, `is_required`,
  `is_repeatable`, `is_unique`, `sort_order`, `validation_rules: dict | None`,
  `options: list[FormFieldOption]`, `is_active`.
- **Business rules:**
  - `add_option(option)` — **options only for `SELECT`/`MULTI_SELECT`**
    (`InvalidFieldOptionError`); duplicate `option_key` → `DuplicateOptionKeyError`.
  - `change_type(new_type)` — switches type; **wipes `options` if the new type is not
    select-like** (silent).
  - `get_option(option_key)`.

#### FormFieldOption (Entity)

- `option_key`, `label`, `value`, `sort_order`, `is_active`. Data-only.

## 7. Project Management

Location: `src/app/domain/project/`, `src/app/application/project/`. **The core domain.**

### 7.1 Domain purpose

- **Business problem:** the heart of the platform — customers publish projects, freelancers
  apply, one is selected, work is started, deliveries are submitted, revisions requested, and
  the project is completed/cancelled, all under strict state-machine control.
- **Responsibilities:** project lifecycle & status history, applications (apply/withdraw/
  decide), deliveries (versioned submissions), revision requests, eligibility of freelancers,
  and multi-aggregate transactions (e.g. accepting a freelancer).
- **Must NOT be responsible for:** the supervisor's QA decision (review context decides it and
  drives project transitions), the customer's final verdict and rating (feedback context), or
  monetization/escrow.

### 7.2 Enums

| Enum | Values |
|---|---|
| `ProjectVisibility` | `PUBLIC`, `PRIVATE`, `INVITE_ONLY` |
| `ProjectPriority` | `LOW`, `NORMAL`, `HIGH`, `URGENT` |
| `BudgetType` | `FIXED`, `RANGE`, `HOURLY`, `NEGOTIABLE` |
| `ProjectStatus` | `DRAFT`, `PUBLISHED`, `COLLECTING_APPLICATIONS`, `ASSIGNED`, `IN_PROGRESS`, `DELIVERY_SUBMITTED`, `UNDER_SUPERVISOR_REVIEW`, `REVISION_REQUESTED`, `AWAITING_CUSTOMER_REVIEW`, `COMPLETED`, `CANCELLED`, `REJECTED`, `ARCHIVED` |
| `ProjectApplicationStatus` | `APPLIED`, `SHORTLISTED`, `ACCEPTED`, `REJECTED`, `WITHDRAWN`, `EXPIRED` |
| `DeliveryStatus` | `SUBMITTED`, `UNDER_REVIEW`, `APPROVED`, `REJECTED`, `REVISED`, `SUPERSEDED` |
| `RevisionRequestStatus` | `OPEN`, `APPROVED`, `REJECTED`, `CLOSED`, `CANCELLED` |

> `ProjectStatus.REJECTED` and `ARCHIVED` are never produced by any Phase-1 flow.
> `ProjectApplicationStatus.EXPIRED` is never produced. `RevisionRequestStatus` beyond `OPEN`
> is never set (only `OPEN` is created; `close()` exists but no use case calls it).

### 7.3 Value Objects

#### Budget

`budget_type`, `fixed_amount`, `min_amount`, `max_amount`, `currency_code`.
- `FIXED` requires `fixed_amount`; `RANGE` requires `min_amount` and `max_amount` with
  `min <= max`; `HOURLY`/`NEGOTIABLE` accept any amounts; `currency_code` non-blank.
- Violations raise `InvalidBudgetError`. **No non-negative check.**

#### ProjectCode

`value: str`, validated by `^PRJ-\d{4}-\d{3,}$` → `InvalidProjectCodeError`.
Generated by `IProjectCodeGenerator` (e.g. `PRJ-2026-001`).

### 7.4 Entities

#### Project (AggregateRoot)

- **Attributes:** `project_code`, `customer_user_id`, `category_id`, `form_template_id`,
  `assigned_supervisor_user_id`, `selected_application_id`, `title`, `description`,
  `visibility`, `priority`, `budget`, `status`, `application_deadline`, `start_at`, `due_at`,
  `completed_at`, `cancelled_at`, `locked_at`, `deleted_at`.
- **State machine** (every mutator first checks `_ensure_unlocked()`; `is_locked()` =
  status in `{COMPLETED, CANCELLED}`):

| Mutator | Allowed from | To | Extra guards / side effects |
|---|---|---|---|
| `publish(at)` | DRAFT | PUBLISHED | — |
| `start_collecting_applications()` | PUBLISHED | COLLECTING_APPLICATIONS | used back-to-back after publish |
| `assign_freelancer(app_id, at)` | COLLECTING_APPLICATIONS | ASSIGNED | `ProjectAlreadyAssignedError` if `selected_application_id` set (one-freelancer rule); sets selection |
| `start(at)` | ASSIGNED | IN_PROGRESS | sets `start_at` |
| `mark_delivery_submitted()` | IN_PROGRESS, REVISION_REQUESTED | DELIVERY_SUBMITTED | — |
| `move_to_supervisor_review()` | DELIVERY_SUBMITTED | UNDER_SUPERVISOR_REVIEW | raises if no `assigned_supervisor_user_id` (**after** mutating) |
| `move_to_customer_review()` | DELIVERY_SUBMITTED **or** UNDER_SUPERVISOR_REVIEW | AWAITING_CUSTOMER_REVIEW | — |
| `request_revision()` | UNDER_SUPERVISOR_REVIEW, AWAITING_CUSTOMER_REVIEW | REVISION_REQUESTED | — |
| `complete(at)` | AWAITING_CUSTOMER_REVIEW | COMPLETED | sets `completed_at` **and** `locked_at` |
| `cancel(at, reason)` | any non-locked status | CANCELLED | sets `cancelled_at` **and `locked_at`** |

- Query helpers: `can_accept_applications()` (`PUBLISHED`/`COLLECTING_APPLICATIONS`),
  `has_supervisor()`, `is_application_deadline_passed(at)` (`application_deadline is not None
  and at > application_deadline`; enforced by `ApplyForProjectUseCase`).

#### ProjectApplication (AggregateRoot)

- `project_id`, `freelancer_profile_id`, `status`, `cover_letter`, `proposed_amount`,
  `proposed_days`, `applied_at`, `decided_by_user_id`, `decided_at`, `decision_note`,
  `withdrawn_at`, `submitted_by_user_id: EntityId | None` (audit field recording who submitted
  the application; set to the actor on the self-service path — see AUTHORIZATION.md §3.2).
- `shortlist()` — only `APPLIED → SHORTLISTED`.
- `accept(decided_by, at)` / `reject(decided_by, at, note)` — only from `APPLIED`/`SHORTLISTED`;
  already decided → `ApplicationAlreadyDecidedError`; else `InvalidStateTransitionError`.
- `withdraw(at)` — only from `APPLIED`/`SHORTLISTED`; not after acceptance.

#### ProjectDelivery (AggregateRoot)

- `project_id`, `version_no`, `submitted_by_user_id`, `status`, `delivery_note`,
  `submitted_at`, `reviewed_at`, `reviewer_user_id`, `superseded_by_delivery_id`,
  `file_asset_ids`.
- `mark_under_review()` / `approve()` / `reject()` / `mark_revised()` — require
  `SUBMITTED`/`UNDER_REVIEW`; `approve`/`reject` stamp reviewer + reviewed_at.
- `supersede(new_delivery_id)` — from any status except already `SUPERSEDED`.

#### ProjectRevisionRequest (Entity)

- `project_id`, `project_delivery_id`, `requested_by_user_id`, `requested_to_user_id`,
  `round_no`, `status`, `reason`, `resolved_by_user_id`, `requested_at`, `resolved_at`.
- `close(resolved_by, at)` — `OPEN → CLOSED`; **never called** by any use case.
- Only `OPEN` is ever created; `requested_to_user_id` is always `None` (the freelancer is never
  explicitly named as the revision target).

#### ProjectStatusHistory (Entity)

- `project_id`, `from_status`, `to_status`, `changed_by_user_id`, `reason`, `changed_at`.
  Pure audit record, written via `record_status_history` helper.

### 7.5 Domain services (`domain/project/services.py`)

- **`RevisionPolicy`** — `MAX_REVISIONS = 3`; `can_request_new_revision(existing_requests)`
  returns `len(existing) < 3`; `ensure_can_request_new_revision(...)` raises
  `MaxRevisionsExceededError`. **Now enforced by every revision-creating path:**
  `RequestRevisionUseCase`, `ReviewDeliveryUseCase` (supervisor reject) and
  `SubmitReviewUseCase` (customer reject).
- **`FreelancerEligibilityPolicy.is_eligible_to_apply(level, project, active_application_count)`**:
  - Returns `False` if `not level.is_active` (fixed).
  - `PUBLIC` requires `level.can_apply_public_projects`.
  - `PRIVATE` requires `level.can_apply_private_projects`.
  - `INVITE_ONLY` → always `False` (no invitation mechanism exists).
  - Cap active applications via `level.max_active_applications`.
  - **Does not check the application deadline** (that is enforced separately by
    `ApplyForProjectUseCase` via `Project.is_application_deadline_passed`).

### 7.6 Repository interfaces

`IProjectRepository` (`add`, `get_by_id`, `get_by_code`, `update`, `list_by_customer`,
`list_available_for_freelancer`, `list_by_supervisor`, `list_by_category`),
`IProjectApplicationRepository` (`add`, `get_by_id`, `find_by_project_and_freelancer`,
`list_by_project`, `count_active_for_freelancer`, `update`),
`IProjectDeliveryRepository` (`add`, `get_by_id`, `get_latest_for_project`, `list_by_project`,
`update`),
`IProjectRevisionRequestRepository` (`add`, `list_by_project`, `count_by_project`, `update`),
`IProjectStatusHistoryRepository` (`add`, `list_by_project`).

### 7.7 Domain exceptions

`ProjectNotFoundError`, `ApplicationNotFoundError`, `DeliveryNotFoundError`,
`ProjectLockedError`, `ProjectAlreadyAssignedError`, `InvalidProjectStatusTransitionError`,
`ApplicationAlreadyDecidedError`, `DuplicateApplicationError`, `MaxRevisionsExceededError`,
`ApplicationDeadlineExpiredError`, `FreelancerNotEligibleError`, `InvalidBudgetError`,
`InvalidProjectCodeError`.

### 7.8 Application helpers

- **`form_validation.validate_form_values(template, form_values)`** — raises
  `FormValidationError` on: unknown `field_id`; missing required value; type checks for
  `NUMBER`, `DECIMAL`, `BOOLEAN`, `DATE`, `DATETIME`, `EMAIL`, `URL`; and **validates
  `SELECT`/`MULTI_SELECT` values against the template's **active** option values** (fixed —
  previously options were not checked). It still ignores `validation_rules`, `is_unique`,
  `is_repeatable`, and inactive fields.
- **`mapping.py`** — `to_project_result`, `to_application_result`, `to_delivery_result`,
  `to_budget_result`. `ProjectResult` now carries `application_deadline`,
  `assigned_supervisor_user_id`, and `selected_application_id` (it omits `start_at`, `due_at`,
  `completed_at`, `cancelled_at`, `locked_at`, `deleted_at`, `form_template_id`);
  `ApplicationResult` now carries `submitted_by_user_id`.
- **`status_history.record_status_history(...)`** — inserts a `ProjectStatusHistory` row.

### Actor

### Input (`AcceptFreelancerCommand`)
- `actor_id`, `application_id`

### Output (`AcceptFreelancerResult`)

## SubmitDelivery

### Purpose
Freelancer submits a delivery; the project routes to supervisor or customer review.

### Actor
The **selected** freelancer of the project.

### Input (`SubmitDeliveryCommand`)
- `actor_id`, `project_id`
- optional: `delivery_note`, `file_asset_ids: list[EntityId]`

### Output (`SubmitDeliveryResult`)
`delivery_id`, `version_no`, `project_status`.

### Dependencies
`IProjectRepository`, `IProjectApplicationRepository`, `IProjectDeliveryRepository`,
`IProjectStatusHistoryRepository`, `IFreelancerProfileRepository`, `ISupervisorReviewRepository`,
`IIdGenerator`, `IClock`, `IUnitOfWork`.

### Flow
1. `get_by_id(project)`; require `selected_application_id` else `PermissionDeniedError`.
2. Load selected application + its freelancer profile; require `profile.user_id == actor_id`.
3. `version_no = (latest.version_no + 1) or 1`; capture `was_revision_requested`.
4. Build `ProjectDelivery(status=SUBMITTED)`; `add`.
5. If a previous delivery exists **and** the project was `REVISION_REQUESTED`:
   `previous.supersede(delivery.id)`; update previous.
6. `project.mark_delivery_submitted()`; history `IN_PROGRESS|REVISION_REQUESTED → DELIVERY_SUBMITTED`.

     `UNDER_SUPERVISOR_REVIEW`.

8. `update(project)`; commit.

### Errors
`ProjectNotFoundError`, `ApplicationNotFoundError`, `FreelancerProfileNotFoundError`,
`PermissionDeniedError`, `ProjectLockedError`, `InvalidProjectStatusTransitionError`.

### Side effects
New delivery (+ optional supersede of the previous one), project status change, history rows,
and a pre-created PENDING supervisor review when routed to a supervisor.

## 8. Quality Assurance / Supervisor Review

Location: `src/app/domain/review/`, `src/app/application/review/`.

### 8.1 Domain purpose

- **Business problem:** after a freelancer submits a delivery, a **category supervisor**
  quality-checks it before it reaches the customer — a gatekeeper step between delivery and
  customer review.
- **Responsibilities:** recording the supervisor's decision (approve/reject) on a delivery,
  listing pending reviews and the supervisor's projects.
- **Must NOT be responsible for:** the project status transitions themselves — those are driven
  by calling `Project.move_to_customer_review()` / `Project.request_revision()`, and the
  delivery state via `ProjectDelivery.approve()/reject()`.

### 8.2 Entity

#### SupervisorReview (Entity)

- **Why it exists:** one QA verdict per delivery per supervisor.
- **Attributes:** `project_delivery_id`, `project_id`, `supervisor_user_id`,
  `decision: ReviewStatus` (default `PENDING`), `reject_reason`, `notes`, `reviewed_at`.
- **Business rules:**
  - `approve(notes, at)` — `PENDING → APPROVED`, stamps notes + reviewed_at.
  - `reject(reason, at)` — `PENDING → REJECTED`, stamps reason + reviewed_at.
  - `_ensure_pending()` — any re-decision raises `InvalidStateTransitionError`.

### 8.3 Enum

`ReviewStatus`: `PENDING`, `APPROVED`, `REJECTED`. (Also reused by the feedback context.)

### 8.4 Repository interface

`ISupervisorReviewRepository`: `add`, `get_by_delivery`, `find_by_delivery`,
`list_pending_for_supervisor`, `update` (code addition vs. `DOMAIN.md`, see §12).

### 8.5 Domain exceptions

`SupervisorReviewNotFoundError`, `NotAssignedSupervisorError`, `DeliveryAlreadyReviewedError`.

### 8.6 Use cases

The three decision use cases share one orchestrator function:
`review_workflow.decide_delivery_review(...)`. `ApproveDelivery`/`RejectDelivery` are thin
wrappers that force the decision.

---

## ReviewDelivery

### Purpose
Records a supervisor's approve/reject decision on a delivery and moves the project forward.

### Actor
A supervisor of the project's category.

### Input (`ReviewDeliveryCommand`)
- `actor_id`, `project_delivery_id`
- `decision: ReviewStatus` (`APPROVED` or `REJECTED`)
- optional: `notes`, `reject_reason`

### Output (`ReviewDeliveryResult`)
`delivery_id`, `project_id`, `decision`, `project_status`.

### Dependencies
`IAuthorizationService`, `IProjectDeliveryRepository`, `IProjectRepository`,
`ICategorySupervisorRepository`, `ISupervisorReviewRepository`,
`IProjectRevisionRequestRepository`, `IProjectStatusHistoryRepository`, `IIdGenerator`,
`IClock`, `IUnitOfWork`.

### Flow (`decide_delivery_review`)
1. Load delivery + project.
2. Status guard: `project.status == UNDER_SUPERVISOR_REVIEW` else
   `InvalidStateTransitionError` (explicit pre-check, fixed).
3. Authorization: `category_supervisor_repo.is_supervisor_of(actor_id, project.category_id)` →
   require `review.decide_own`; otherwise require `review.decide_any` (admin bypass).
4. `review_repo.find_by_delivery` — if a review exists and is not `PENDING` →
   `DeliveryAlreadyReviewedError`. Otherwise reuse the existing PENDING review (created by
   `SubmitDelivery`) or build a new one.
5. Inside the UoW:
   - **APPROVED:** `review.approve(notes, now)`; `delivery.approve(actor_id, now)`;
     `project.move_to_customer_review()`; target `AWAITING_CUSTOMER_REVIEW`.
   - **REJECTED:** `RevisionPolicy.ensure_can_request_new_revision(existing)` (3-round cap
     **now enforced**); `review.reject(reject_reason or "No reason given", now)`;
     `delivery.reject(actor_id, now)`; create an **OPEN** `ProjectRevisionRequest`
     (`round_no = len(existing)+1`, `requested_to_user_id=None`); `project.request_revision()`;
     target `REVISION_REQUESTED`.
   - Other decision → `ValidationError`.
   - Record history `UNDER_SUPERVISOR_REVIEW → target`; persist the review via
     `review_repo.update(review)` when reusing an existing one or `review_repo.add(review)` for
     a new one (fixed); `delivery_repo.update`; `project_repo.update`; commit.

### Errors
`DeliveryNotFoundError`, `ProjectNotFoundError`, `NotAssignedSupervisorError`,
`PermissionDeniedError` (missing `review.decide_own`/`review.decide_any`),
`DeliveryAlreadyReviewedError`, `MaxRevisionsExceededError`, `ValidationError`,
`ProjectLockedError`, `InvalidStateTransitionError`.

### Side effects
Review recorded, delivery decided, project moves to customer review (approve) or revision
requested (reject), history recorded, revision request created on reject (capped at 3).

> **Remaining gaps (§12):** `supervisor_user_id` on a reused review keeps the
> originally-assigned supervisor, not the deciding actor; `review_repo.get_by_delivery` is dead
> code; the `is_supervisor_of` check is bypassed by the `_any` (admin) tier rather than enforced
> via the entity, and authorization is checked **after** loading the project (not as the first
> step).

### Flow
1. Generate code for `now.year`.
2. Build `Ticket(status=OPEN, assigned_to=None)`.
3. Build `TicketParticipant(role=REQUESTER, joined_at=now)`.
4. In UoW: `add(ticket)`, `add(participant)`; commit.

### Errors
None (no validation; subject not checked for blank).

### Side effects
Ticket + requester participant.

> **Gaps:** empty `subject` allowed; `actor_id` not verified to exist; no duplicate-code check
> (delegated to repository).

## AssignTicket

### Purpose
Assigns a ticket to a user and adds them as an ASSIGNEE participant.

### Actor
A participant of the ticket with permission `ticket.assign`.

### Input (`AssignTicketCommand`)
- `actor_id`, `ticket_id`, `assignee_user_id`

### Output (`AssignTicketResult`)
`ticket_id`, `assigned_to_user_id`.

### Dependencies
`IAuthorizationService`, `ITicketRepository`, `ITicketParticipantRepository`, `IIdGenerator`,
`IClock`, `IUnitOfWork`.

### Flow
1. `require_permission(actor_id, "ticket.assign")`.
2. `get_by_id(ticket)`; `ensure_participant(actor_id)`.
3. `ticket.assign(assignee)`; if assignee not a participant, add
   `TicketParticipant(role=ASSIGNEE, joined_at=now)`.
4. `update(ticket)`; commit.

### Errors
`PermissionDeniedError`, `TicketNotFoundError`, `NotTicketParticipantError`.

### Side effects
Assignee set (+ new participant if needed).

> **Gaps:** closed tickets can be assigned; no check `assignee != actor` or that assignee exists;
> an assignee who is already a participant keeps their old role (no upgrade to `ASSIGNEE`).

## 11. Reporting & Analytics

Location: `src/app/domain/reporting/`, `src/app/application/reporting/`. **Read-only.**

### 11.1 Domain purpose

- **Business problem:** aggregated, system-wide statistics for dashboards and analytics.
- **Responsibilities:** exposing read-only statistics (users, projects, freelancers,
  customers) via a single query port.
- **Must NOT be responsible for:** any write operation — it has no mutable entities and no
  write-side methods.

### 11.2 Read models (`domain/reporting/read_models.py`)

| Model | Fields |
|---|---|
| `DashboardStatistics` | `total_users`, `active_projects`, `total_freelancers`, `total_revenue: Decimal` |
| `UserStatistics` | `total_users`, `verified_users`, `active_users` |
| `ProjectStatistics` | `created`, `completed`, `cancelled` |
| `FreelancerStatistics` | `total_freelancers`, `approved_freelancers`, `pending_freelancers`, `average_rating: Decimal \| None` |
| `CustomerStatistics` | `total_customers`, `active_projects`, `completed_projects` |
| `SystemAnalytics` | composite of the five above (`dashboard`, `users`, `projects`, `freelancers`, `customers`) |

`SystemAnalytics` is a code addition not in `DOMAIN.md` (see ARCHITECTURE.md §6).

### 11.3 Repository interface

`IReportingReadRepository`: `get_dashboard_statistics`, `get_user_statistics`,
`get_project_statistics`, `get_freelancer_statistics`, `get_customer_statistics`.
No `get_system_analytics` — the composite is assembled by the use case.

### 11.4 Use cases

All six use cases share one pattern: constructor
`(authorization_service: IAuthorizationService, reporting_read_repo: IReportingReadRepository)`;
`execute(ReportingQuery(actor_id))` first calls
`require_permission(actor_id, "reporting.read")` then delegates. `ReportingQuery` is the only
command DTO (a single `actor_id` field).

- **`GetDashboardStatistics`** → `DashboardStatistics`.
- **`GetUserStatistics`** → `UserStatistics`.
- **`GetProjectStatistics`** → `ProjectStatistics`.
- **`GetFreelancerStatistics`** → `FreelancerStatistics`.
- **`GetCustomerStatistics`** → `CustomerStatistics`.
- **`GetSystemAnalytics`** → calls all five read methods and composes `SystemAnalytics`.

### Errors
All raise `PermissionDeniedError` when the actor lacks `reporting.read`.

### Side effects
None (read-only).

> **Note:** queries are **unparameterized** — no date ranges, scoping, filters, or pagination;
> `average_rating: None` means "no ratings yet".

## 12. Cross-Cutting Analysis

### 12.1 Permission-key inventory (code-truth)

Authorization is enforced **only** through `IAuthorizationService.require_permission(user_id, key)`,
with a single shared helper `authorize_owned_action` for the two-tier `_own`/`_any` pairs.
Permission keys are declared as `PERMISSION_*` constants. The four system roles (`admin`,
`customer`, `freelancer`, `supervisor`) are immutable for removal/revocation. The full,
code-verified inventory:

| Permission key | Where enforced |
|---|---|
| `user.assign_role` | `iam.assign_role` |
| `user.remove_role` | `iam.remove_role` (also guards `SystemRoleImmutableError`) |
| `user.grant_permission` | `iam.grant_permission` |
| `user.revoke_permission` | `iam.revoke_permission` (also guards `SystemRoleImmutableError`) |
| `user.activate` | `iam.activate_user` |
| `user.block` | `iam.block_user` |
| `freelancer.approve` | `freelancer.approve_freelancer`, `freelancer.reject_freelancer` |
| `freelancer.assign_level` | `freelancer.assign_freelancer_level` |
| `category.manage` | `category.create_category`, `category.update_category`, `category.delete_category` |
| `category.assign_supervisor` | `category.assign_supervisor` |
| `category.remove_supervisor` | `category.remove_supervisor` |
| `form.manage` | all 7 form use cases (create/update/publish template, add/update/remove field, add option) |
| `project.create` | `project.create_project` |
| `project.apply` | `project.apply_for_project` |
| `project.manage_own` / `project.manage_any` | `project.publish/cancel/start/complete`, `accept_freelancer`, `reject_freelancer`, `request_revision`, `view_applications` |
| `review.decide_own` / `review.decide_any` | `review.review_delivery`, `review.approve_delivery`, `review.reject_delivery` |
| `feedback.manage_own` / `feedback.manage_any` | `feedback.submit_review`, `feedback.submit_rating` |
| `ticket.assign` | `ticketing.assign_ticket` |
| `ticket.read_own` / `ticket.read_any` | `ticketing.get_user_tickets` |
| `ticket.close_own` / `ticket.close_any` | `ticketing.close_ticket` |
| `reporting.read` | all 6 reporting use cases |

Owned-resource use cases (`project.*`, `review.*`, `feedback.*`) use the `_own`/`_any` pair via
`authorize_owned_action`: the resource owner holds the `_own` permission; any other actor
(an admin) must hold `_any`. `GetProjectDetails`, `GetMyProjects`, `GetAvailableProjects`,
`GetCategories`, `GetCategoryProjects`, `GetFormTemplate`, and the read queries have **no**
permission gate in Phase 1.

### 12.2 Code vs. design docs — deviations

The authoritative rule is: the **code is authoritative**. Since the previous revision, the
following previously-flagged gaps were **resolved** in code:

- **Revision cap** is now enforced on **all** revision-creating paths (`RequestRevision`,
  supervisor reject via `decide_delivery_review`, customer reject via `SubmitReview`).
- **Application deadline** is now enforced by `ApplyForProjectUseCase` (`Project.is_application_deadline_passed`).
- **Dynamic-form `SELECT`/`MULTI_SELECT`** values are now validated against the template's active options.
- **Forgot-password enumeration leak** removed (`exists_by_email` probe, no `UserNotFoundError`).
- **`review_repo.update`/`add`** are now used correctly (update for reused, add for new).
- **`RequestRevision` history** now records the true source status (captured before mutation).
- **`Project.cancel`** now sets `locked_at`.
- **`GrantPermission`** now rejects duplicates (`PermissionAlreadyGrantedError`).
- **`GetUserTickets`** is now authorized (`ticket.read_own`/`ticket.read_any`).
- **`RemoveRole` / `RevokePermission`** now guard `is_system` roles (`SystemRoleImmutableError`).
- **Reliable supervisor removal**: `RemoveSupervisorUseCase` promotes the next active supervisor.
- **`CreateProject`/`Register`** default-role & ownership checks unchanged.

The remaining current deviations follow:

| # | `DOMAIN.md`/`APPLICATION.md` says | Code does | Impact |
|---|---|---|---|
| 1 | Delivery routed via a configurable policy | `SubmitDelivery` **hard-codes** supervisor routing, pre-creates a PENDING `SupervisorReview`; customer-review path is unreachable via a delivery | `DeliveryRoutingPolicy` never consulted |
| 2 | RefreshToken flow | `RefreshToken` token is **never persisted** to validate; refresh/rotate creates a new one | Refresh effectively honours only the in-memory chain |
| 3 | Forgot-password + reset | `ForgotPasswordUseCase` sends a token that is **never persisted/expired**; **no reset-password use case** | Incomplete auth flow (enumeration leak fixed) |
| 4 | `User.suspend()` / availability | `User.suspend()`, `FreelancerProfile.set_availability`, `Resume.mark_as_current()` are defined but **never invoked** by any use case | Dead domain surface |
| 5 | Availability/schedule domain services | `UserAvailabilityPolicy`, schedule/availability rules exist but are never invoked | Unreachable rules |
| 6 | Soft-delete (`deleted_at`) | Present on `Ticket`, `TicketMessage`, `User` but **never set** | Dead columns |
| 7 | `INVITE_ONLY` project | Eligibility **always rejects** `INVITE_ONLY` | Invite-only mode unusable |
| 8 | Ticket lifecycle | Only `OPEN → CLOSED` reachable; `ARCHIVED`, `IN_PROGRESS`, `WAITING_*` unreachable | Dead states |
| 9 | `SystemAnalytics` read model | Composite model + `GetSystemAnalytics` are code additions not in `DOMAIN.md` | Added value; undocumented |
| 10 | Reporting queries | Unparameterized — no date range, scope, filter, or pagination | Coarse analytics |

### 12.3 Gaps & unclear rules (open questions for Phase 2)

1. **`move_to_supervisor_review()`** mutates status, then raises if no
   `assigned_supervisor_user_id` — the invariant check happens *after* the state change. The
   use case avoids it by gating on `project.has_supervisor()`, so the defect is latent.
2. **`ReviewDelivery`** reuses the PENDING review created by `SubmitDelivery` but keeps the
   *original* `supervisor_user_id`; the deciding admin on the `_any` path does not re-stamp it.
   Authorization is also checked **after** loading the project (not as the first step), and the
   `is_supervisor_of` probe is bypassed entirely by the `_any` tier.
3. **`SubmitRating`** does not require the referenced customer review to be `APPROVED` — with
   only a `find_by_project` interface it may reference an older REJECTED review.
4. **Reporting queries are unparameterized** (no date range, scope, filter, or pagination) and
   `average_rating: None` semantics are unclear.
5. **Form section reorder** (`ReorderSectionsUseCase`) likely uses sequential positions with no
   conflict handling; `ListAvailableForFreelancer` doesn't filter by category, deadline, or
   eligibility (the deadline check lives only in `ApplyForProjectUseCase`).
6. **`DomainError`→HTTP mapping** (ERROR_HANDLING.md) is a Phase-2 contract, not yet enforced.
7. **`WithdrawApplication`** reports a foreign application as `PermissionDeniedError`, while
   `UpdatePortfolioItem`/`DeletePortfolioItem` hide existence with `NotFoundError` — the
   hide-vs-deny policy is inconsistent across contexts.
8. **`LoginUser`** checks only `status`, not `deleted_at` (unlike `RefreshTokenUseCase`), so a
   soft-deleted-but-ACTIVE user could still log in (deleted_at is never set in Phase 1).
